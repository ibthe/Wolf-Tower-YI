# Wolf Tower: версия для YouTube и Instagram. Анализ и принятые решения

## 1. Что изменено

| Область | Было (WhatsApp) | Стало (YouTube + Instagram) |
|---|---|---|
| Профили | один, `match_all`, UDP-обход | два профиля по SNI (`youtube`, `instagram`), `block_quic` у обоих |
| Выбор сервисов | нет | переключатели в Android и desktop, сохраняется между запусками |
| Стратегии | 20, часть с UDP (`-a1`) | 29, только TLS/TCP: `split+disorder`, `tlsrec`, `fake3/6+disorder` и 9 цепочек (раздел 5) |
| Проба автоподбора | рукопожатие + 40 КБ | у YouTube: 100 КБ за 4 с (ловит замедление), у Instagram как раньше |
| Автоподбор | всегда все кандидаты | досрочный выход, когда у каждого сервиса уже есть вариант с полным баллом |
| ByeDPI | без общих флагов | `-X` (только IPv4) в рабочем и пробном запуске |
| Дизайн | зелёный | тёмная тема YouTube (#0F0F0F, красный #FF0000), градиент Instagram, значки сервисов, иконка приложения перекрашена |

Лицензионная система (`License.kt`, `license.js`, ключи) не менялась. `applicationId` тоже: версия ставится поверх WhatsApp-сборки. Если нужна параллельная установка, поменяйте `applicationId` в `android/app/build.gradle.kts`.

## 2. Находки по коду (каждая проверена в исходниках)

1. **Матчинг доменов суффиксный.** В ByeDPI `--hosts` сравнивает по границе точки (`host_cmp` в `mpool.c`), поэтому одной записи `googlevideo.com` хватает на `rr1---sn-xxxx.googlevideo.com`. Перечислять CDN-узлы не нужно.
2. **IPv6 не утекает через DNS.** `hev-mapped-dns.c` отвечает только на A-запросы (на AAAA пустой ответ), приложения получают лишь IPv4-адреса и IPv6-мимо-туннеля для YouTube/Instagram (у Google и Meta он широко развёрнут) не возникает.
3. **Но сам ByeDPI мог уйти на IPv6.** По умолчанию он резолвит `AF_UNSPEC`, и на двойном стеке пробы и реальный трафик могли пойти по пути, который не совпадает с проверенным. Флаг `-X` (`--no-ipv6`) есть в таблице опций (в README его нет) и фиксирует `AF_INET`. Добавлен в `StrategyArgs.BASE` и в оба запуска, пользовательская строка его задать не может.
4. **QUIC главное для YouTube.** ByeDPI не умеет нормально десинхронизировать QUIC, зато умеет TLS поверх TCP. Поэтому `-U` включается автоматически (оба профиля `block_quic`), клиенты откатываются на TCP. На desktop браузеры и так не шлют QUIC через SOCKS-прокси.
5. **Старая проба не видела замедление.** YouTube чаще замедляют, чем блокируют: рукопожатие проходит, а скорость падает. Проба с порогом 40 КБ и таймаутом на каждое чтение это пропускала, и вариант «без обхода» мог победить при реальном троттлинге. Теперь для YouTube страница должна дойти до 100 КБ за 4 с (≈200 кбит/с, ниже типичного троттлинга). Тот же порог не применён к самопроверке во время работы: перегрузка сети не должна запускать смену стратегии и перезапуск ByeDPI посреди воспроизведения.
6. **`disorder` одним флагом не работает на Windows** (README ByeDPI). Для desktop сделана и поставлена первой `split+disorder` (`-s1+s -d3+s`), это рекомендованная связка и для Linux/Android.
7. **TTL фейков зависит от оператора.** Добавлены TTL 3 и 6 к 4, 8, 12: DPI на мобильных сетях обычно в 2-6 переходах от абонента.
8. **UDP-варианты** (`*+udp`, `-a1`) убраны из списка: при заблокированном QUIC они только тратят время подбора. В библиотеке остались, чтобы не ломать сохранённые настройки.

## 5. Цепочки разрезов (как `-d1 -s1+s -s3+s -s6+s ... -a1`)

Идея семейства: ClientHello режется на много кусков с растущими смещениями от начала SNI, часть разрезов делается `disorder` (`-d`) или `oob` (`-o`), так что DPI, собирающий только первые пакеты или ограниченное число фрагментов, не видит имя целиком. Ваш пример (`chain`) уже был в списке, добавлены ещё 9 вариантов. Все без `-a1`: при заблокированном QUIC UDP-часть бесполезна.

| Имя | Аргументы | Источник |
|---|---|---|
| `chain-oob` | `-o1 -s1+s -s3+s -s6+s -s9+s -s12+s -s15+s -s20+s -s30+s` | обсуждение ByeDPI на ntc.party (YouTube) |
| `chain-mix` | `-d1 -s1+s -d3+s -s6+s -d9+s -s12+s -d15+s -s20+s -d25+s -s30+s -d35+s` | тестовый список ByeByeDPI |
| `chain-mix2` | `-o1 -s1+s -d1+s -s3+s -d6+s -s12+s -d14+s -s20+s -d24+s -s30+s` | ntc.party (YouTube) |
| `chain-dis` | `-d1 -d3+s -s6+s -d9+s -s20+s -d25+s -s30+s` | ntc.party |
| `oob-rec-split` | `-o1 -d1 -r1+s -s1+s -d3+s` | тестовый список ByeByeDPI |
| `oob-sack` | `-s1 -q1 -Y -f-1 -r1+s` | ntc.party, без автогрупп `-A`; `-Y` только Linux/Android |
| `chain-tlsrec` | `-r1+s -s1+s -s3+s -s6+s -s9+s -s12+s -s15+s -s20+s -s30+s` | своя: цепочка поверх разрезания TLS-записи |
| `chain-fake` | `-f-1 -t 8 -s1+s -s3+s -s6+s -s9+s -s12+s -s15+s -s20+s -s30+s` | своя: цепочка с фейк-пакетом |
| `chain-fine` | `-s1+s -s2+s -s3+s -s4+s -s5+s -s6+s -s7+s -s8+s` | своя: мелкие куски вокруг SNI |

Варианты с автогруппами (`-At,r,s` и т.п.) не включены: приложение само переключает стратегии по результатам проб. Любую другую строку можно ввести вручную в «Дополнительно», допустимы флаги `-s -d -o -q -f -t -r -a -Y` и другие обходные. Порядок в списке идёт от мягких к агрессивным, при равном результате побеждает более ранняя.

## 3. Ограничения, о которых нужно знать честно

- **Не проверялось на реальных сетях операторов**: в среде разработки нет сети. Проверено: 23 теста desktop (включая интеграционные с настоящим собранным `ciadpi`), все 29 стратегий в итоговой командной строке принимаются парсером. Какая стратегия сработает у вашего оператора, определит автоподбор на устройстве.
- **Android-код не компилировался** (нет Android SDK). Правки в Kotlin небольшие, скобки и импорты проверены, но первая сборка в CI может потребовать мелких правок.
- **Instagram может не поддаваться DPI-обходу.** Если оператор блокирует адреса Meta по IP (чёрная дыра), а не по SNI, приёмы с пакетами бессильны: TCP-соединение вообще не устанавливается. Диагностика в приложении (`Diagnose.kt`) это показывает, и в таком случае нужен VPN или прокси. YouTube блокируется и замедляется по SNI, там DPI-обход обычно работает.
- **Замедление после рукопожатия** на самом видеопотоке (`googlevideo.com`) проба проверяет косвенно, через `www.youtube.com`. Прямой скорости воспроизведения она не измеряет.
- **ECH** (шифрование SNI) обход по SNI сделает невозможным, если сервисы его включат. Сейчас у Google и Meta для этих доменов ECH не используется.
- На Android через туннель идут только приложения из списка пакетов (официальные YouTube, YouTube Music, Kids, Studio, ReVanced, Instagram, Instagram Lite). Браузерный YouTube на телефоне не покрыт: добавьте пакет браузера в `profiles.json` (`android_packages`), тогда он тоже пойдёт через туннель (желательно только при необходимости).
- Строгий Private DNS (DoT) на телефоне обходит mapdns. При проблемах переключите на «Автоматически» или включите DoH в приложении.

## 4. Как собрать

- Desktop: `cd desktop && npm install && npm test` (тесты) и `npm start`.
- Android: как раньше, через Gradle/CI. `profiles/profiles.json` копируется в ассеты сборкой.
- Проверка стратегий на реальном ByeDPI: `make -C third_party/byedpi`, затем `WT_TEST_CIADPI=$PWD/third_party/byedpi/ciadpi node desktop/test/run.js`.
